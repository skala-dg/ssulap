# 써랍 (SSULAP)

취업 준비생이 기본 이력·경력·경험을 정리하고, 회사별 자기소개서를 작성하면서 필요한 기록과 검토 메모를 함께 참고하는 취업 준비 서비스입니다.

프론트 화면, 데이터 모델, REST API가 동일한 사용자 흐름과 업무 규칙을 표현하도록 구성했습니다.

## 주요 기능

### 로그인과 자소서 검토

- 등록된 계정 중 하나를 선택하는 로그인
- 사용자별 기본 이력·경력·경험·자소서 작업공간 분리
- 작성 완료 자소서의 검토자 선택과 받은·보낸 검토 요청함
- 검토자의 읽기 전용 자소서 조회와 문항별 메모
- 검토 완료 후 작성 화면 자료 서랍에서 현재 문항의 메모 확인
- 친구 관계, 링크 공유, 이메일·푸시 알림, 인라인 댓글은 범위에서 제외

### 기본 이력

- 학력·자격증·어학·병역·보훈·장애사항을 구역별로 저장
- 저장한 구역은 읽기 전용으로 전환하고, `수정` 버튼으로 언제든 다시 편집
- 병역에서 `해당 없음`을 선택하면 군별·계급·복무 기간을 비활성화하고 기존 입력값을 정리
- 자격증과 어학 성적 여러 건 추가·삭제
- 학력 영역에서 수강 과목 목록 펼치기·접기
- 전공명, 수강연도, 학기, 과목명, 과목유형, 취득학점, 성적, 재수강 여부 입력
- 수강 과목을 Excel에서 열 수 있는 CSV 파일로 다운로드

### 경력과 경험

- 경력 등록·수정
- 경험 등록·수정·삭제, 검색 및 태그 필터
- 경험을 상황·과제, 내 역할·행동, 결과, 배운 점, 협업 회고, 경험 개요로 구분해 기록
- 경험과 경력의 내용을 자소서 작성 화면에서 조회·복사하고, 경험은 문항의 참고 자료로 연결

### 자소서 보관함과 작성 화면

- 회사·직무·지원 시기별 자소서 생성 및 진행률 확인
- 문항 추가·삭제·순서 변경·이전/다음 이동
- 경험·경력·완료된 검토 메모를 작성 화면 옆에서 동시에 조회
- 참고한 경험이나 경력을 누르면 오른쪽 아래 비차단 상세 패널로 표시
- 상세 패널이 열린 상태에서도 자소서 계속 작성 가능
- 답변 입력과 별개인 `문항 작성 완료` 버튼 제공
- 문항별 글자 수와 글자 수 초과 상태 표시
- 문항 전체를 합산한 글자 수는 표시하지 않음

### 자동 저장과 답변 버전

- 마지막 입력 후 **2초 동안 추가 변경이 없으면** 현재 브라우저에 자동 저장
- 화면 이동이나 상태 변경 시에는 대기 중인 내용을 즉시 저장
- 자동 저장은 현재 초안만 갱신하며 과거 버전을 만들지 않음
- `버전 저장` 버튼으로 문항별 수동 스냅샷 생성
- 버전 기록을 참고 자료와 동일한 비차단 상세 패널에서 조회
- 저장된 답변 복사·복원 및 수동 저장 버전 삭제
- 복원 시 현재 초안을 바로 덮어쓰며 복원 직전 백업은 생성하지 않음
- 작성 완료본과 제출 완료본은 보호되어 사용자가 직접 삭제할 수 없음

자소서 상태는 `작성 중 → 작성 완료 → 제출 완료` 순서로 인접 단계만 변경합니다. 모든 문항을 명시적으로 완료하고 글자 수 제한을 지켜야 자소서를 작성 완료로 바꿀 수 있습니다. 작성 완료 또는 제출 완료 상태에서는 편집을 잠그고, 이전 단계로 되돌린 뒤 다시 편집할 수 있습니다.

버전 보관 정책은 다음과 같습니다.

| 자소서 상태 | 문항별 보관 범위 |
|---|---|
| 작성 중 | 최근 작업 버전 20개 + 이전 제출본 최대 1개 |
| 작성 완료 | 작성 완료본 + 최근 작업 버전 5개 + 이전 제출본 최대 1개 |
| 제출 완료 | 최종 제출본 1개 |

## 프론트 데이터 저장 방식

프론트에서는 입력 데이터를 브라우저 `localStorage`의 `ssulap-workspace-v3` 키에 저장합니다. 기존 `ssulap-workspace-v2` 데이터는 테스터1 작업공간으로 한 번 이전합니다.

- 새로고침 후에는 같은 브라우저에서 작성 내용을 복원합니다.
- 브라우저 저장 공간을 지우면 예시 데이터로 초기화됩니다.
- Git에는 소스 코드와 설계 문서만 올라갑니다.
- **다른 컴퓨터로 Git 저장소를 옮겨도 기존 컴퓨터의 `localStorage` 데이터는 이동하지 않습니다.**
- 수강 과목 다운로드는 조회된 데이터를 브라우저에서 CSV 파일로 변환하므로 별도 API를 사용하지 않습니다.
- 경험 추천은 문항과 경험 태그를 기준으로 관련 경험을 선별합니다.

## 실행 방법

Node.js LTS와 npm이 필요합니다.

```bash
git clone https://github.com/skala-dg/ssulap.git
cd ssulap
npm ci
npm run dev
```

터미널에 표시되는 로컬 주소로 접속합니다. 배포용 빌드 확인은 다음 명령으로 실행합니다.

```bash
npm run build
npm run preview
```

## 다른 컴퓨터에서 이어서 작업하기

현재 컴퓨터에서 변경한 파일을 확인한 뒤 README만 올리려면 다음과 같이 실행합니다.

```bash
git status
git add README.md
git commit -m "docs: 서비스 설계 문서 정리"
git push origin main
```

다른 컴퓨터에서는 처음이면 위의 `git clone` 절차를 사용하고, 이미 복제한 저장소가 있다면 다음과 같이 최신 코드를 받습니다.

```bash
git switch main
git pull origin main
npm ci
npm run dev
```

`main` 브랜치로 푸시하면 `.github/workflows/deploy-pages.yml`이 GitHub Pages 빌드·배포를 실행합니다. GitHub Pages 경로를 위해 Vite의 base는 `/ssulap/`으로 설정되어 있습니다.

## 프론트엔드 구조

```text
src/
├── App.vue                         # 공통 레이아웃과 화면 선택
├── views/                          # 로그인, 기본 이력, 경력, 경험, 보관함, 작성·검토 화면
├── components/
│   ├── applications/              # 참고 자료 서랍과 비차단 상세·버전 패널
│   ├── dialogs/                   # 경력·경험 등록/상세 다이얼로그
│   ├── layout/                    # 사이드바, 상단바, 푸터
│   └── profile/                   # 자격증, 어학, 수강 과목 영역
├── composables/useWorkspace.js    # 공유 상태, 자동 저장, 버전·상태 정책
├── data/demoData.js               # 초기 예시 데이터
└── utils/applicationMetrics.js    # 진행률, 글자 수, 저장 시각 계산
```

초기의 큰 `App.vue`는 화면·도메인별 파일로 분리되어 있습니다. 기능을 추가할 때는 화면 표현은 `views`와 `components`, 공유 상태와 동작은 `useWorkspace.js`, 계산 로직은 `utils`에 두는 현재 구조를 유지합니다.

## 데이터·API 설계 산출물

백엔드 개발자가 화면 흐름과 업무 규칙을 그대로 구현할 수 있도록 API 명세와 데이터 모델을 함께 관리합니다.

| 파일 | 내용 |
|---|---|
| `docs/ssulap-design.md` | 서비스 범위, 관계, 상태 전이, 삭제·트랜잭션 정책 |
| `docs/ssulap-DB.dbml` | PostgreSQL 기준 16개 테이블과 관계 |
| `docs/ssulap-API.yml` | OpenAPI 3.0.3 기반 36개 경로, 65개 작업, 36개 스키마 |
| `docs/ssulap-api-catalog.md` | 화면별 REST API 목록과 저장·완료·버전 흐름 |
| `docs/ssulap-data-dictionary.md` | 필드 타입, 필수 여부, enum과 제약 조건 |
| `docs/ssulap-validation.json` | 문서 구조와 빌드 검증 결과 |

주요 설계 엔터티는 사용자, 프로필, 학력, 수강 과목, 자격증, 어학 성적, 경력, 경험, 태그, 지원서, 자소서 문항, 문항 버전 및 연결 테이블입니다. 프론트엔드 기능을 변경할 때 관련 API·DB 정책도 함께 수정해야 합니다.
