[참고] 세부 평가 기준 웹 서비스 개발구분핵심 관점반드시 포함해야 할 내용주의사항
서비스 정의 (서비스 명확성 / 실현 가능성)“무엇을 왜 만드는가” + 전체 기준 역할•명확한 서비스 목적 및 타겟 사용자 정의•구체적인 문제 정의 (원인, 배경, 현황 포함)•문제를 해결하는 논리적이고 타당한 기능 제안•서비스 개요 ↔ 기능 요구사항 간 일관성•액터별 기능 정의와 화면 설계 연결•기능이 문제 해결과 연결되지 않음•과도하게 큰 범위 (비현실적 서비스)
UI 흐름 및 화면 설계“서비스를 어떻게 사용하게 할 것인가”•서비스 요구사항의 모든 기능이 UI 흐름에 반영•주요 화면 목록 및 사용자 흐름 정의•화면 구성 요소 구체화 (버튼, 입력, 데이터)•예외/오류 시나리오 포함 (가점)•UI ↔API 데이터 필드 일치•핵심 기능이 UI에 없음•UI 데이터와 API 불일치
데이터 모델(ERD)“서비스와 UI를 가능하게 하는 데이터 구조”•서비스 기능을 지원하는 모든 엔터티 정의•UI에서 사용하는 모든 데이터 필드 포함•PK/FK 명시 및 관계 정의 (1:N, M:N)•속성 데이터 타입 및 제약조건 명시•API 구조와 일관성 유지•UI 데이터가 ERD에 없음•API와 데이터 모델 불일치
API 명세“서비스·UI·데이터를 연결하는 인터페이스”
•모든 서비스 기능을 수행 가능한 API 정의•UI 화면별 필요한 API 제공•Request/Response가 ERD와 일치•적절한 HTTP Method 사용•Path / Query / Body 명확히 정의•에러 코드 정의 (400, 401, 404 등)•공통 스키마 재사용 ($ref)
•UI에서 필요한 API 누락•API와 데이터 모델 불일치
